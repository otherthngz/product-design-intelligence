# Visual-design integration and scenario re-review

**Date:** 2026-11-14. This is a repeat review by the same assistant, not an independent assessment or a controlled agent benchmark. No user testing was performed. The earlier [practical audit](practical-audit.md) remains the baseline; scores below use its 0–5 scale for routing, reasoning, evidence and delivery. The new skill was applied to the dashboard; unchanged scenarios were re-read, not regenerated by separate agents.

## Skill added

The [frontend-design skill](../../.agents/skills/frontend-design/SKILL.md) is an unmodified copy from [Anthropic's upstream skill](https://github.com/anthropics/skills/tree/main/skills/frontend-design) at commit `2c5958ecac7cee2b583967a2c4981d0f4a75c579`, retrieved 2026-11-14. Its [Apache 2.0 license](../../.agents/skills/frontend-design/LICENSE.txt) is included. The PDI router now selects it alongside `ui-prototyping` when visual direction is relevant and alongside `ux-audit` for visual critique; it is not needed for text-only tasks. User instructions and existing product design systems take precedence. No automatic activation or cross-host compatibility was tested.

## Dashboard comparison

[Before](../../examples/analytics-dashboard/before.html) · [After](../../examples/analytics-dashboard/index.html) · [Decision log](../../examples/analytics-dashboard/README.md)

The original reused the onboarding demo's green palette, serif display headline and separated rounded cards. The revision uses a restrained blue-neutral palette, one type family and a shared metrics strip; the page title names the task, and the flagged account list appears before the activity chart. This makes the information order more directly aligned with the stated *assumed* account-review task. A style change alone does not prove better usability or originality; a conventional data workspace may be appropriate for the task. Users and a real design system must determine whether these choices fit.

**Observed remaining issues:** the flagged list is only two fictional examples while the summary reports 9 or 12; the interface no longer displays an author-facing sample notice and cannot offer a complete review list; the example documentation identifies the data as fictional. Names are not links and there is no follow-up action; metric definitions, real dates, empty/loading/error states and an actual flagging method do not exist. The activity chart depends on the table for exact values. These are prototype limits, not a tested product workflow.

**Verification performed:** in the in-app browser, switching to the previous period updated the status, summary and sample table. At 390 × 844 the layout stacked without page-level horizontal overflow; pressing Tab from the period selector focused the named accounts-table scroll region. The desktop layout was visually reviewed. This is not a complete keyboard, screen-reader, contrast or cross-browser assessment. Automated simulated-DOM state tests were also run separately; they do not establish browser or design quality.

## Next review

Run realistic requests with independent reviewers and different host agents; compare task completion and comprehension with representative users, verify actual brand and design-system constraints, and test keyboard, zoom, assistive technology, contrast and browsers. Do not equate a different palette or a score with validated design quality.
