# Limitations and next steps

- The host supplies model reasoning, skills discovery, permissions and tools. Only the local example-copy path is implemented here; no model or general adapter runtime is bundled. Compatibility with specific agent products has not been tested.
- The routing and evaluation cases are instructions and manual cases, not automated model evaluations. Structural tests cannot prove reasoning, usability or accessibility.
- The sample is fictional and stores nothing. It has no authentication, service, persistence, network errors, analytics or real product data.
- Enterprise mode documents suggested practices, not implemented approval workflows, audit trails, policy enforcement, role-based access control, or security/privacy certification.
- No user research, usability study, screen-reader audit or accessibility conformance assessment has been performed.

Suggested next iteration: (1) run and record realistic evaluations across actual hosts and reviewers; (2) test the example with keyboard, screen readers, zoom and more devices and improve it based on findings; (3) add a host-specific adapter only after a real integration need is established; (4) supply real project context and research before using the design for production.

The knowledge library is manually curated; it does not autonomously retrieve, learn, or enforce review. Roadmap charts were not accessible in the reviewed text; see the [source registry](../../knowledge/sources.yaml). The [practical audit](practical-audit.md) documents five worked scenarios and remaining gaps.
