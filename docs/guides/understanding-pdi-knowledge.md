# Understanding PDI's knowledge

PDI's knowledge is a small set of practical references an AI assistant can consult while designing. It currently covers five topics: setting product outcomes, organizing tasks, designing consistent components, reviewing AI-assisted work, and building responsive accessible interfaces. Each topic has basic concepts, hands-on advice and deeper trade-offs. It is a starting point, not a complete education or proof the assistant is an expert.

For example, if you ask, “Design a dashboard that helps account managers choose which accounts to review,” PDI can use product guidance to ask what decision matters, UX guidance to order information around that decision, design-system guidance to keep cards consistent, and frontend guidance to build a responsive page with a text table. AI guidance reminds the assistant to label uncertain interpretations. See the [dashboard example](../../examples/analytics-dashboard/README.md).

Give the assistant your goal, audience, existing evidence, constraints and files. You can request a specific skill or topic: “Use product framing and the product outcomes topic to define success for this onboarding feature.” The output should identify what came from you, what was observed, and what remains an assumption or hypothesis. A recommendation is a proposal; ask what evidence would change it and which checks actually ran.

To contribute, propose a correction with a reliable source and a concrete example. A person should review consequential changes before adopting them. Follow [contributing knowledge](contributing-knowledge.md); no programming knowledge is required to suggest a change.
