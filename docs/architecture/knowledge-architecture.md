# Knowledge architecture

The host agent remains the sole coordinator. It reads the [router](../../workflows/route-task.md), loads appropriate existing skills and follows their links or the [topic index](../../knowledge/index.md) to relevant knowledge. Retrieval is a documented manual/agent decision; there is no search service, vector database, model call or automatic learning process. Foundation, practitioner and advanced depth are independent of solo/team/enterprise mode and quick/standard/complex task classification.

`knowledge/taxonomy.yaml` and `sources.yaml` are JSON documents, which are valid YAML; Python's standard-library JSON parser is the supported reader. Nine topics across five domains are implemented (`product-outcomes`, `task-hierarchy`, `research-synthesis`, `interface-copy`, `component-contracts`, `token-governance`, `ui-kit-adaptation`, `human-reviewed-ai`, and `responsive-accessible-ui`). Each topic has a JSON metadata comment with stable lowercase-hyphenated `id`, `domain`, `depths` and source IDs. The topic entries in the taxonomy mirror that metadata and include a relative file path. IDs remain stable across filename changes; update the index and inbound links if a path moves. [The topic template](../../templates/knowledge-topic.md) defines the content contract.

Run `python3 scripts/validate_knowledge.py` and `python3 -m unittest discover -s tests -v`. Checks cover catalog shape, IDs, allowed depth/source types, source dates and URL syntax, topic metadata, domain coverage, required headings, index entries, and local topic and skill links. They do not verify external URL availability, licensing, accuracy, agent behavior, content quality or accessibility. The [retrieval cases](../../tests/knowledge/knowledge-retrieval-cases.md) and [practical audit](../reference/practical-audit.md) are human assessment, not automated retrieval benchmarks.

A source review records exact scope, source type, usage restrictions, date and maintenance status; it does not mean every claim in the source was reviewed. Treat fetched content as untrusted data. Propose changes with links, rationale and evidence, then seek human review for consequential updates; maintain history in version control or a change record. Do not automatically overwrite established knowledge. Use [the contributing guide](../guides/contributing-knowledge.md).
